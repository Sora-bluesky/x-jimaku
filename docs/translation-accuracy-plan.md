# 翻訳精度向上プラン

> 2026-08-25 起草。根拠: v0.3.0 の実動画対訳検証（8 cue 中 6 正確・誤訳ゼロ・劣化 2 件の原因分解）。
> ステータス: sora へ提案中（実行順の承認待ち）。

## 前提（実測から）

- Chrome Translator は与えられた英語を忠実に訳す（翻訳器起因の誤りは検出されず）
- 劣化の実測原因: ①ASR 誤り（OpenAI→OpenHit・疑問形化）②節分割（「制約。」単体 cue）
- よって効くのは「翻訳器に入る英語の質」= ASR と節分割・文脈

## P0: 計測基盤

- 精度ベンチハーネス: （音声・正解転写・正解訳)のテストセット（実動画数本 + TTS）。
  正解転写は Gemini（agy）生成。WER（認識）+ LLM 採点（訳質）を 1 コマンドで before/after 比較。
  受入: 数値が再現可能に出ること。改善は以後すべてこのベンチで判定する。

## P1: 即効レバー（実測で問題確認済み）

1. 極短節の連結: 3 語以下の節は次節と連結してから翻訳（「制約。」問題）
2. X ポスト由来の動的固有名詞辞書: ポスト本文・@mention・引用 RT から固有名詞を抽出し、
   認識後テキストに辞書補正を適用してから翻訳（OpenHit→OpenAI 型に直効。X 固有の無料文脈）
3. 幻覚フィルタ強化: Silero VAD（plan.md v0.2 路線）+ 定型幻覚句（"Please subscribe..." 等）の
   ブラックリスト

## P2: ASR 強化（最大レバー）

4. モデル自動推奨: adapter info（取得済み）で RTX 級なら small/turbo を推奨表示。
   既定変更はベンチの WER 実測を見てから
5. 文脈条件付け: 確定済み直前テキスト + 固有名詞辞書を Whisper の initial prompt に注入。
   **要スパイク**: transformers.js の pipeline が prompt/prefix 指定をサポートするか

## P3: 翻訳段の上積み（ベンチで採否）

6. 文脈付き翻訳: 前 1〜2 節を添えて翻訳し当該節のみ表示（文境界マーカー方式で抽出信頼性を確保。
   v2 設計レビューで「既定無効が安全」とされた項目の再挑戦）
7. Prompt API（Gemini Nano）再訳のベンチ比較: 文脈を渡せる分自然な訳の可能性。ローカル・無料。
   Translator と並べて数値で採否

## 実行順の推奨

P0 + P1 を 1 バッチ（Sol 1〜2 巡）→ ベンチ数値を確認 → P2 → P3。
各施策の受入はベンチの WER / 訳質スコアの改善で判定（主観判定をしない）。
