## D1（42-2 P1）: 猶予中の CS_TRANSLATE を background が defer する

現状: 猶予エピソード中に offscreen が CS_TRANSLATE を出すと、relayOffscreenTranslationRequest
が content port 不在で即 failure 応答 → TranslationEngine が content-translator を session
恒久 failPath。1 回の 3s 断で以降の日本語翻訳が死ぬ（translator バックエンド利用時）。

変更: background は「対象 tab に生きている猶予エピソードがある」間、CS_TRANSLATE を
失敗応答せず **エピソード紐付きの待ちキュー（上限 4・超過は最古を failure 応答）**に積む。
resume ACK で content port へ順に流す。エピソード満了時はキュー全件に従来どおりの
failure 応答（このとき failPath されるのは現行挙動と同じで、実際に翻訳不能なので正しい）。

## D2（42-1 P1）: content の送信バッファに CS_TRANSLATE_RESULT を追加

現状: postContentMessage のバッファ対象は CS_PCM / CS_EOS のみ。猶予中に完了した
content translator の結果（CS_TRANSLATE_RESULT）は無音破棄され、offscreen 側の
pendingContentTranslations が永久 pending → TranslationEngine.processing が true のまま
固着し、再接続後も全行未翻訳。

変更:
- CS_TRANSLATE_RESULT を送信バッファの対象種別に追加（既存 FIFO を共用・容量は現行 16 のまま。
  PCM 12 + 余裕 4 の設計に result 数件が同居しても、溢れは最古 PCM drop = 既存の意図的挙動）
- **backstop**: offscreen の pendingContentTranslations に timeout（15s・定数）を追加。
  timeout 時は当該 promise を reject し、エンジンの既存 catch（failPath → 次経路）に落とす。
  正常系では D1/D2 により発火しない。固着だけを断つ安全網

## D3（42-3 P2）: EOS 抑止フラグを再 tapping でクリア

現状: contentEosCompleteRequestId は ACK（ended-awaiting-resume）で set 後、同一 request の
再生再開 → 再 tap → 通常 stop（video-removed 等）が来ても :1641 の抑止で無視され、
タップ無しのままキャプチャが回り続ける。

変更: handleContentTapState が同一 requestId の state "tapping" を見たら
contentEosCompleteRequestId を null に戻す（再 tap = EOS 状態の終了）。

## D4（40-1 P2）: relay カウンタ flush を遷移点へ集約

現状: flush は stopping→idle 経路と failActiveCaptureUnexpectedly の 2 箇所に個別配置。
error への直接遷移（content tap error / offscreen 報告 error 等）で漏れる余地がある。

変更: moveCaptureState（または遷移の共通点）で「active 系 → idle/error」の遷移を検出したら
flushPcmRelayDropCounts() を 1 箇所で呼ぶ。既存 2 箇所の個別呼び出しは削除（二重 flush 防止。
flush は冪等だが、集約が正）。

## D5（40-2 P2）: offscreen rejected PCM の停止時 flush

変更: handleCaptureStop（と capture の異常終了経路）で rejectedPcmChunkCount が非ゼロなら
サマリを 1 回出してからリセット。レート制限窓内に埋もれた分を停止時に必ず可視化。

## D6（40-3 P2）: cue-drop warn のレート制限

変更: overlay の drop ループの console.warn を 5s レート制限付きの集約
（「dropped N waiting cues since last report」+ 累積 droppedCueCount）に変更。
host.dataset.cueDrops の更新は毎回のまま（テスト・実機計測の一次データ）。

## D7（41-1 P1）: bench 既定 backend を製品既定に揃える

変更: bench/run-bench.mjs の DEFAULT_BACKEND を "auto" → "prompt-api"。
CfT では LanguageModel が使えず Translator へフォールバックするため実測挙動は変わらないが、
「bench 既定 = 製品既定」の整合を回復する。--backend フラグは従来どおり。
