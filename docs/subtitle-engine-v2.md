# 字幕エンジン v2 設計 — 安定コミット型ローリング字幕

> 2026-08-25 起草。根拠は Grok 一次情報調査（Netflix TTSG / ARIB TR-B14 運用 / NHK 技研 /
> Chromium Live Caption 実装 / UFAL whisper_streaming / Google CHI 2023 / STACL wait-k /
> Google re-translation ICASSP 2020）。ステータス: **Sol Max 設計レビュー → sora 承認待ち**。

## 1. 現行方式の診断

現行（〜PR #16）は「成長バッファを毎回全文再転写 → 暫定を 2 秒ごと全文再翻訳 → 1 行を置換表示」。
これは研究文献の **re-translation 方式**（Google ICASSP 2020）に相当し、以下が構造的欠点:

- 暫定英語が毎パス書き換わる（Whisper は同じ音声でも仮説前半が揺れる）
- 日本語は語順が英語と逆転するため、全文再翻訳のたびに**文頭から書き換わる**（ジッタ最大）
- CHI 2023（Google）: ライブ字幕の快適度を最も損なうのは「既表示テキストの変化」。精度より安定が優先

## 2. 新方式: 3 段の確定パイプライン（すべて append-only）

```
Whisper 仮説列 ─→ [A] LocalAgreement-2 確定器 ─→ 確定英語 prefix（不変）
                        │
                        └→ [B] 節スプリッタ（., ? ! , 接続詞 or 10 語）─→ 節（不変単位）
                                │
                                └→ [C] 節ごとに 1 回だけ翻訳 → 日本語節（不変）→ ローリング表示へ append
```

### [A] LocalAgreement-2（テキスト空間限定・音声バッファは現行のまま）

**設計レビュー反映（blocking 1）**: Whisper worker は時刻情報を返さない（タイムスタンプ契約の拡張は
語長不定で切断位置を決められず欠落/重複リスク）。よって **agreement はテキスト空間のみ**で取る:

- 音声バッファ管理（リング・committedOffset・無音/強制コミットでの前進）は**現行の時間ベースのまま**。
  切断は従来どおり無音境界/強制境界でのみ行う（音声を単語位置で切らない）
- 連続する 2 回の転写出力を**正規化後**（小文字化・空白/句読点正規化）に単語列で比較し、
  最長共通接頭辞を「確定英語」に昇格。確定分は以降不変。表示・翻訳はこの確定列だけを消費する
- **打ち切り規則（blocking 2）**: 同一区間の agreement が **6 秒**進まない場合は最新仮説を強制採用して
  前進（幻覚的な揺れ・仮説停止での無期限停滞を防ぐ）。現行の 8 秒強制コミットは音声側の上限として維持
- 遅延の目安: 平均 3.3 秒（UFAL・平均値であり上限ではない）。**上限保証の対象は待機時間のみ**: agreement 待機 ≤6 秒・音声側境界 ≤8 秒。転写・翻訳の処理時間と表示キュー待ちはこれに加算される（低速端末では伸びる。RTF>1 の端末は現行同様バックプレッシャで隙間が空く）

### [B] 節スプリッタ

- 確定英語を `. ? !` / カンマ + 等位接続詞 / 10 語超で節に分割。分割済み節は不変
- Netflix 改行規則（句読点後・接続詞前で切る、名詞句の途中で切らない）を節境界に採用

### [C] 節単位翻訳（wait-k の節版）

- 節ごとに Chrome Translator を 1 回呼ぶだけ。**再翻訳は廃止**（現行の interim 再翻訳・2 秒スロットル・
  単一スケジューラの複雑さがまるごと消える）
- 直前 1〜2 節を文脈として同時に渡し、出力は当該節分のみ表示（文脈切れ対策・任意）
- ja 検出スキップ・4 段フォールバック・翻訳未使用バッジは現行のまま

## 3. 目標値（2026-08-25 sora 指定）と表示方式

**目標: YouTube の自動翻訳字幕と同等の表示品質。** sora が「違和感を感じないレベル」と指定した
基準の実体は次の 3 点（YouTube 非ライブの自動字幕 + 自動翻訳は事前生成のため）:

| KPI | YouTube 自動翻訳 | v2 目標 |
|---|---|---|
| 表示後の書き換え | 0 回（事前確定） | **0 回**（LocalAgreement + 節コミットで達成） |
| 表示単位 | 節/文のセグメント（表示中は不変・次で丸ごと交代） | 同方式 |
| 行数・長さ | 1〜2 行・フレーズ長 | 1〜2 行・1 行全角 14 字 |
| 初出遅延 | 0 秒（事前処理・ライブでは原理的に不可） | 3〜4 秒（ライブの下限に挑戦） |

**表示: YouTube 型セグメント置換**（ローリング行送りではなく）:

- 確定した日本語節を 1〜2 行（全角 14 字/行）に収まる**セグメント（cue）**へまとめて表示。
  各 cue は cueId を持ち、**表示中の本文変更は禁止**。次の cue が確定したら丸ごと交代
- cue 最短表示 1.5 秒。**キュー規律（blocking 3）**: 待ち上限 2 cue。超過時は ①待ち cue を連結して
  2 行表示で消化 ②連結しても収まらない場合は最短表示を 1.0 秒へ短縮 ③それでも溢れる場合は
  **最古の待ち cue を破棄**し、破棄数を console と診断パネルに記録（サイレント欠落にしない）
- 発話停止で 5 秒 fade（現行踏襲）。バー geometry（固定高・全幅・コントロール帯 44px 回避・
  popover fullscreen・チップ）は現行踏襲。高さは 2 行分に固定
- 暫定テキストは**既定で非表示**（確定のみ = 原則 1）。オプション「暫定を薄字で表示」（既定 OFF・
  UD トーク方式のグレー）を settings に用意
- showOriginal=true は対応する英語確定節を小さい下段に併記（2+1 行 geometry）

## 4. トレードオフ（sora 判断材料）

| 項目 | 現行 | v2 |
|---|---|---|
| 初出遅延 | 約 2 秒（暫定） | 約 3〜4 秒（確定のみ） |
| 書き換わり | 毎 2 秒・文頭から | **ゼロ**（append のみ） |
| 読みやすさ | 読んでいる途中で消える/変わる | 放送字幕と同じ読み方ができる |
| 翻訳呼び出し | 2 秒ごと全文 | 節ごと 1 回（総量減） |
| コード | スケジューラ + 版管理 + 復活防止で複雑 | append-only で大幅簡素化 |

遅延 +1〜2 秒は「再生速度を落とす」Tips とも相殺可能。安定性の向上が UX 上の本命（CHI 2023）。

## 5. 実装スコープ（承認後）

- segmenter v2: LocalAgreement-2 確定器（単語アライメント・共通接頭辞）
- translate: 節キュー化（スケジューラ・interim 系・版管理・復活防止ガードの大部分を削除）
- overlay: ローリング 2 行レンダラ（append・行送り・保持時間）
- 検証（blocking 4 の KPI 厳密化）: **cueId 単位の本文不変性**をアサートする —
  ハーネスは MutationObserver で cue 要素を追跡し、①同一 cueId の textContent 変化 = 失敗
  ②許可される遷移は「cue 生成 → 表示 → 削除」と「A 削除 → B 表示」の交代のみ、と定義する

## 6. 入力クラス判定表（設計レビュー指摘の補完）

| 入力クラス | 期待挙動 |
|---|---|
| 言い直し・数値/固有名詞の揺れ（fifteen/fifty 等） | agreement 不成立のまま 6 秒で最新仮説を強制採用。採用後の訂正はしない（表示不変が優先） |
| 幻覚反復・無音区間 | 現行のエネルギー VAD で無音セグメントは転写に投げない（維持）。反復検出は**幻覚と識別できる条件に限定**: 新しい音声がほぼ増えていない再転写間で同一 n-gram の反復が増殖した場合のみ除外（= 音声時間の増分に対して不自然な増殖）。実発話の反復（「だめ、だめ、だめ」等・音声が実際に進んでいる）は正規に確定・表示する |
| 非英語（日本語等）混入 | 現行の CJK ヒューリスティック維持: 日本語は翻訳スキップで cue 化。その他言語は英語扱いで翻訳へ（誤訳は許容・スコープ外） |
| 15 秒超・無句読点の連続発話 | 音声側 8 秒強制境界で必ず前進。節スプリッタは句読点がなければ 10 語で強制分割し、日本語 cue が 28 字（2 行）超なら文節近似（読点・助詞境界）で再分割 |
| 引用符・URL・数式読み上げ | 引用符内・URL トークンは分割禁止の保護範囲。保護範囲が 10 語制限と衝突する場合は保護を優先し次の境界まで延長 |
| 高速発話でキュー滞留 | §3 のキュー規律（連結 → 短縮 → 最古破棄 + 記録） |
| 発話停止 → 再開 | 停止: キュー全消化後に 5 秒 fade。再開: 新しい agreement 系列として開始（旧状態は持ち越さない） |
| セッション停止/復元 | 現行の watermark・セッション世代・復活防止の責務を cue 機構に引き継ぐ（Sol notes 指摘の維持項目） |
- 規模: M2〜M4 の中核 3 ファイルの再設計。1 バッチ（Sol）+ Grok レビューで 1 巡を想定
