## 4-1 モデル自動推奨（options ページ・表示のみ）

### 事実

- adapter.info は options で取得済み: probeWebGpu（options/index.ts:974-1010）→
  readAdapterInfo（:1490-1524）が vendor / architecture を抽出し診断表示に使用中
- モデル select: options.html:401-406（tiny/base/small/turbo）。既定 base
- モデル別 WER の実測記録は docs に**ゼロ**（推奨文言の根拠はベンチで作る）

### 変更

- 純関数 `recommendModel(info: {vendor?: string; architecture?: string} | undefined,
  device: "webgpu" | "wasm" | undefined): WhisperModel | null` を新設（テスト可能）
  - wasm / adapter なし → "tiny"
  - vendor "nvidia" かつ architecture が離散 GPU 世代（turing / ampere / ada / lovelace /
    blackwell を含む文字列）→ "turbo"（実測で small と比較して決定 — 下記スパイクと同時測定）
  - vendor "nvidia" その他・"amd" / "intel" の判別不能帯 → null（推奨を出さない。
    誤推奨は無推奨より悪い）
- 表示: モデル select の直下に 1 行（例: 「この GPU なら turbo を推奨」+ 現選択が推奨と
  一致なら非表示）。**表示のみ・自動変更しない**（sora 既定: 推奨表示）
- 根拠づくり: リリース前に実機（RTX 4070）で bench --model small / turbo を各 1 run 取り、
  WER とレイテンシを HANDOFF に記録して推奨先を確定する

## 4-2 Whisper initial prompt スパイク（実験 → 採否判定）

### 仮説

固有名詞（context terms は既に content が収集し CS_PCM に同載）や直近の確定文を Whisper の
initial prompt（decoder の先行文脈）として与えると、固有名詞の認識と文体の一貫性が上がる。

### スパイク手順（採否はベンチ数値で決める — 精度議論は必ずベンチ数値の流儀）

1. transformers.js の whisper pipeline が initial prompt 相当（`prompt` /
   `initial_prompt` / decoder_input_ids 前置）をサポートするかを node_modules 実査で確認
   （Sol 設計レビューの必須確認項目）
2. サポートあり → whisper.worker に optional の initial-prompt 経路を実装し、
   bench に `--initial-prompt` フラグを追加
3. tts / tibo で A/B（各 3 run・WER / properNounRecall / fragmentRate）
4. 改善が分散を超えたら本採用（segmenter からの動的注入設計へ）、超えなければ記録して закрыть

### 受け入れ条件

- 4-1: recommendModel の単体テスト（判定表全行）+ 実機 options で推奨行の目視 +
  推奨先を決めた bench 実測値が HANDOFF に記録されていること
- 4-2: A/B 実測表（run ごとの生値）と採否判定の記録
- 共通: typecheck / build / 既存テスト / Grok レビュー
